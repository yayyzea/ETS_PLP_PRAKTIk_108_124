# Log Penggunaan AI

Catat setiap penggunaan AI atau coding agent yang memengaruhi kode atau laporan.

| No | Siapa | Prompt / tugas (ringkas) | Hasil: diterima, diubah, atau ditolak | Alasan | Cara verifikasi |
| --- | --- | --- | --- | --- | --- |
| 1 | Zahra | Membantu memahami dan memperbaiki lexer agar keyword SQL tidak peka terhadap huruf besar-kecil, tanpa mengubah penulisan identifier. | Diterima | Penggunaan `text.upper()` untuk membandingkan keyword sesuai kebutuhan, sementara teks identifier tetap dipertahankan. | Menjalankan pengujian lexer dan memeriksa token untuk keyword huruf kecil serta identifier. |
| 2 | Zahra | Penanganan komentar blok multiline dan komentar yang tidak ditutup pada lexer. | Diubah | Arahan AI digunakan sebagai dasar, lalu disesuaikan dengan struktur pemindaian karakter pada `crud/lexer.py`. | Menjalankan `test_regresi_komentar_blok_multiline` dan memeriksa bahwa komentar dilewati serta komentar yang tidak ditutup menghasilkan `LexError`. |
| 3 | Zahra | Perbaikan presedensi operator logika `AND` dan `OR` pada parser. | Diterima | Pemisahan parsing ke fungsi `_and()` dan `_logical()` sesuai dengan grammar yang mengharuskan `AND` memiliki presedensi lebih tinggi daripada `OR`. | Menjalankan `test_regresi_presedensi_and_or` dan memeriksa struktur hasil parsing ekspresi. |
| 4 | Zahra | Penambahan dukungan `LEFT OUTER JOIN` pada parser. | Diterima | Parser menerima keyword `OUTER` sebagai bagian opsional setelah `LEFT`, tanpa mengubah penanganan `LEFT JOIN`. | Menjalankan `test_parser_left_outer_join` dan memeriksa bahwa satu statement terbentuk tanpa parse error. |

| 8 | Zahra |  Masalah CLI, seperti diagnostic Resolver yang tidak memengaruhi exit code dan penanganan error pada mode --ast, sebagai kandidat Bug Report. |  Ditolak | Walaupun masalah CLI memang diperbaiki, kandidat tersebut tidak dipilih karena Bug Report difokuskan pada bug Lexer dan Parser yang memiliki test regresi khusus di tests/test_tambahan.py. | Membandingkan kandidat dengan ruang lingkup Bug Report dan memastikan bug yang dipilih memiliki test regresi relevan. |
| 9 | Zahra |  Penanganan beberapa file dengan nama dasar yang sama sebagai Bug Report. |  Ditolak |  Kasus diuji menggunakan file same.sql yang dibuat khusus untuk menguji kondisi nama file duplikat, bukan berasal dari masalah utama yang ditemukan pada file proyek. Selain itu, file tersebut dihapus setelah pengujian selesai karena hanya berfungsi sebagai file sementara untuk menyimulasikan kondisi nama file duplikat dan bukan merupakan bagian dari berkas proyek maupun dataset pengujian utama. | Memeriksa konteks pengujian dan memastikan file dengan nama sama memang dibuat khusus untuk pengujian tersebut. |

**Refleksi (3-5 kalimat).** Di bagian mana AI paling membantu? Di mana AI keliru atau
menyesatkan, dan bagaimana kalian mengetahuinya?
AI paling membantu dalam memahami alur program, menemukan penyebab kesalahan pada Lexer, Parser, Resolver, dan CLI, serta memberikan saran perbaikan dan pengujian regresi. AI juga membantu menyusun pembagian tugas, mengevaluasi hasil pengujian, dan merapikan dokumentasi proyek. Namun, beberapa saran AI tidak sepenuhnya sesuai dengan kondisi proyek, misalnya mengusulkan kasus pengujian file dengan nama dasar yang sama sebagai Bug Report utama, padahal kasus tersebut dibuat secara khusus untuk pengujian dan bukan berasal dari masalah utama pada file proyek. Ada pula saran yang perlu disesuaikan agar tidak bertentangan dengan implementasi dan pembagian tugas anggota. Hal tersebut diketahui dengan memeriksa kembali kode sumber, hasil pengujian, riwayat perubahan, spesifikasi tugas, serta kontribusi masing-masing anggota sebelum menerima atau menerapkan saran AI.
